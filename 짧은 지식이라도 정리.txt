참고로  그래서 나온게 비동기프로그래밍 
Java Virtual Threads: 최근 자바 21 버전에서 나온 기술로, 쓰레드를 수만 개 만들어도 컨텍스트 스위칭 비용이 거의 들지 않게 혁신을 일으켰습니다.

1. 기존 쓰레드 vs 가상 쓰레드
지금까지 우리가 대화한 쓰레드는 **플랫폼 쓰레드(Platform Thread)**라고 부릅니다. 이건 OS(운영체제)가 관리하는 일꾼이라서 만들기도 무겁고(1MB 점유), 개수도 제한적이었죠.
하지만 자바 21의 가상 쓰레드는 다릅니다.
기존 방식 (1:1 매칭): 자바 쓰레드 1개 = OS 쓰레드 1개 (무겁고 비쌈)
가상 쓰레드 (M:N 매칭): 수만 개의 가상 쓰레드가 소수의 OS 쓰레드 위에서 돌아감 (매우 가볍고 쌈)


2. OS가 하던 일을 자바가 가로채다
기존에는 쓰레드를 바꾸는 권한이 OS(운영체제) 커널에 있었습니다.
기존 (OS 컨텍스트 스위칭): "자, 이제 1번 쓰레드 멈춰! CPU야, 1번의 모든 정보를 하드웨어 레지스터에서 메모리로 옮겨 적어! 그리고 2번 정보를 다시 CPU에 세팅해!"
이 과정은 집 전체의 이삿짐을 싸고 푸는 것만큼 무거운 작업입니다. CPU 입장에서는 엄청난 낭비죠.
자바 21 (가상 쓰레드): "OS야, 넌 가만히 있어. 내가 관리하는 가상 쓰레드 1번이 지금 DB 기다린대. 내가 내 메모리 안에서 1번 상태만 잠깐 기록해두고, 바로 2번 데이터로 갈아 끼울게."
이건 이사가 아니라, 보던 책에 책갈피를 끼우고 옆에 있는 다른 책을 펼치는 정도의 가벼운 작업입니다.

즉 cpu가 직접 계산하는것보다 이미 계산된(1번쓰레드가 어디까지 작업했는지) 내용을 
자바 메모리에 저장해놓아서 그걸 그냥 사용
